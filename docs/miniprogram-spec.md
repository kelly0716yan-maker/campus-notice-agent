# 校园通知助手 小程序体验版：需求说明（给 Claude Code 的开发依据）

## 目标

做一个**最小可用**的微信小程序，让 10–20 位同学在自己手机上试用，验证：
1. 他们会不会持续把群通知贴进来（复用）；
2. 提取结果有没有用、哪里不对（纠错反馈）。

**只做下面列出的功能，其他都不做。**

## 功能范围（MVP）

一个页面：
1. 顶部一行提示：“请先去掉通知里的姓名、学号、电话等个人信息。”
2. 多行输入框：粘贴通知原文（最多 3000 字，超出提示并截断）。
3. 按钮“提取”：调用云函数，显示 loading，失败时给出友好提示并可重试。
4. 结果卡片，显示：事项、活动时间、截止时间、地点、对象、要做什么。值为“未提及”的字段灰色显示。底部一行小字：“结果由 AI 生成，请核对关键信息。”
5. “原文依据”：默认折叠，点开显示 evidence。
6. 按钮“复制成文字”：复制成下面格式的文字（跳过值为“未提及”的行），方便粘贴到备忘录或提醒事项。
```
【事项名称】
截止时间：…
活动时间：…
地点：…
对象：…
要做什么：…
```
7. 反馈：“👍 准确” / “👎 有误”。点“有误”弹出可选输入框：“哪里不对？”（可不填）。
8. 勾选框（默认不勾）：“允许把这条通知（已去掉个人信息）用于改进产品”。勾选且提交反馈时，才保存原文。

**不做：** 用户画像、相关性判断、日历文件、待办列表、登录注册、分享、历史记录。

## 云函数

### `extract`
- 输入：`{ text, today }`（today 由小程序传入，格式 YYYY-MM-DD，用手机当天日期）。
- 校验：`text` 为空或超过 3000 字就返回错误。
- 调用 DeepSeek：
  - 地址 `https://api.deepseek.com/chat/completions`，模型 `deepseek-chat`；
  - `temperature: 0`，`max_tokens: 800`，`response_format: {"type": "json_object"}`；
  - system 提示词使用本仓库 `src/extractor.py` 里的 **`PROMPT_V05`，一字不改**，复制到 `cloudfunctions/extract/prompt.js`；
  - user 消息格式：`今天日期：{today}\n通知来源：未知\n通知原文：\n{text}`。
- 解析返回的 JSON；解析失败时重试 1 次，仍失败返回错误。
- 返回：`{ ok: true, data: {title, event_time, deadline, location, audience, action, evidence}, prompt_version: "v0.5" }`。
- **API Key 只放在云函数的环境变量 `DEEPSEEK_API_KEY` 里**，不能写进代码，不能提交到 GitHub，不能出现在小程序前端。
- **超时：** 云函数默认超时时间很短，必须改到 20–30 秒（具体上限以控制台为准），否则大模型还没返回就会超时。
- **限流：** 每位用户（openid）每天最多 30 次，超出返回“今天的次数用完了，明天再来”，用来控制费用。
- **不保存通知原文。** 只有用户勾选了“允许用于改进”并提交反馈时，才在 `feedback` 里保存原文。

### `feedback`
- 输入：`{ rating: "up" | "down", reason?, consent: boolean, text?, result? }`。
- 写入集合 `feedback`：`{ _openid, rating, reason, consent, text(仅 consent 为 true 时保存), result(仅 consent 为 true 时保存), prompt_version, ts }`。

### `track`
- 输入：`{ type }`，type 取 `open`（打开小程序）、`extract`（提取成功）、`copy`（点了复制）。
- 写入集合 `events`：`{ _openid, type, ts }`。不存任何通知内容。

## 数据集合

| 集合 | 字段 | 用途 |
|---|---|---|
| `events` | _openid, type, ts | 算复用：一周内有 2 天以上使用的用户数 |
| `feedback` | _openid, rating, reason, consent, text, result, prompt_version, ts | 点踩率；经同意的通知加入评测集 |
| `usage_daily` | _openid, date, count | 每日限流 |

## 隐私

- 在小程序后台补好“用户隐私保护指引”，说明会收集的信息（使用记录、用户主动提交的反馈）。
- 不收集手机号、学号、姓名；不使用任何画像。
- 集合权限设为“仅创建者可读写”或仅云函数可访问，前端不能直接读别人的数据。

## 验收标准

1. 用 `data/test2_notices.csv` 里第 3、8、10 条通知测试，三条都能返回合法 JSON，且：
   - 第 3 条：event_time、deadline 都是“未提及”，没有编造报名方式；
   - 第 8 条：event_time 为 2026-01-16 15:00，deadline 为“未提及”，地点含“腾讯会议”；
   - 第 10 条：deadline 为 2026-03-09 17:00，event_time 为“未提及”。
2. 输入为空、超长、断网、模型返回非 JSON 时，都有友好提示，不会白屏。
3. 一位用户一天调用超过 30 次会被拦下。
4. 勾选“允许用于改进”时才保存原文；不勾选时，数据库里查不到任何通知内容。
5. 在真机上可用（不只是开发者工具里）：用“体验版”打开，复制成文字后能粘贴到备忘录。
6. 代码里搜不到 API Key。

2. 上传代码，设为**体验版**；**开发版只有开发者自己能用，朋友打不开**。
