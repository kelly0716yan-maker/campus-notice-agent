# Agent 设计（V0.5）

## 为什么需要 Agent，而不只是抽取

用户访谈里，4/5 的同学想要提醒联动，也有人说“看完就忘”。只把通知整理成卡片还不够，要让系统**判断这条通知和我有没有关系**，并**替我把事情放进日历和待办**。这需要三样东西：记忆、判断、工具。

## 三个能力

| 能力 | 做法 | 在代码里 |
|---|---|---|
| 记忆 | 保存用户画像（年级、学院/专业、身份、关注方向），本地存储，不上传 | `user_profile.py` |
| 判断 | 结合画像判断相关程度（高/中/低），并给出一句理由 | `agent.py`，`report_relevance` 工具 |
| 工具调用 | 生成日历文件（含提前 1 天、30 分钟提醒）、保存待办 | `agent_tools.py`，`create_calendar_event`、`add_todo` 工具 |

## 流程

```
通知原文 → extract（V0.5 提示词）→ 结构化信息（事项/活动时间/截止时间/地点/对象/行动）
                                       │
              用户画像 ────────────────┤
                                       ▼
                         Agent（大模型 + 3 个工具，最多 5 轮）
                         1. report_relevance：必须先判断相关程度
                         2. 相关程度高/中 → create_calendar_event、add_todo
                         3. 相关程度低 → 不调用其他工具
                                       ▼
                         相关程度 + 日程文件(.ics) + 待办
```

## 设计取舍

- **日历只生成文件，不直接改用户日历。** 用户点击下载并导入后才生效，错了也不会污染日历。
- **工具参数只能来自已提取的信息。** 没有具体日期就不创建日程；时间格式不对时，工具会把错误返回给模型，让它修正。
- **最多循环 5 轮**，防止模型反复调用工具停不下来。
- **画像里没填的信息不猜。** 判断依据只能是画像和通知里写明的条件。
- **画像和待办只存本机**，已加入 `.gitignore`，不会被提交到 GitHub。
- 相关性判断用“相关 / 不相关”和用户自己的标注比较（`run_agent_eval.py`），工具函数有离线单元测试（`tests/test_agent.py`），不需要 API Key 就能运行。

## 已知限制

- 相关性判断只用 10 条通知、一个人的画像评测过，样本很小，不代表对所有同学都准。
- 画像由用户自己填，没有自动学习，也不会根据用户的操作更新。
- 日历提醒时间固定为提前 1 天和 30 分钟，还不能自定义。
